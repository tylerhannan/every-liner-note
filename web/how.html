01

One month of Discogs, one shelf, one database

Everything on the record comes from two places: the monthly Discogs data dump, which is the whole catalogue as CC0, and the CSV export of my own collection. ClickHouse does the rest. Every number on the page comes out of a SQL query you can open, and, if you connect a ClickHouse of your own, run again.

  1. Discogs data dump12.7 GB of gzipped XML: 19.6M releases, 10.3M artists, 2.6M albums, 2.4M labels
  2. discogskitturns the XML into flat Parquet in about six minutes, sub-tracks and all
  3. ClickHouseINSERT … SELECT FROM file() loads it into MergeTree in about 40 seconds: 252M credits, 182M tracks, 67M person-to-album edges
  4. My shelfthe Discogs collection export, loaded alongside
  5. Buildruns every query on the page and writes the results to static files, in about 20 seconds
  6. This pagestatic HTML on GitHub Pages. No server, unless you bring one
02

What runs when

Once a month
Download the dump, convert it, load it. Discogs publishes a full snapshot each month rather than changes, so the whole thing gets rebuilt. It's cheap enough that this is fine.
Once per build, with AI
ClickHouse's AI functions run once, at build time, and never on the live page. aiClassify sorts the 85,688 ways Discogs describes vinyl colour into plain colours (the 2,013 most common phrases so far, about 95% right on a random check), and aiGenerate writes the short notes about the people on my shelf. Locally that's a small model through Ollama; in ClickHouse Cloud it's the same SQL with a bigger one.
Every time you open the page
Nothing touches a database. The numbers are baked in from the last build.
When you press Run live
The page sends the exact query from that panel to the ClickHouse you connected, and shows what came back and how long it took. You can edit the SQL first. Use a read-only user.
When you hover over a sleeve
The cover is fetched from the Discogs API for that one record, kept for under six hours as their terms ask, and credited to Discogs.
03

Where ClickHouse earns its keep

  • Is vinyl just old albums again? 22 million rows, about a tenth of a second.
  • The colour chart looks up the colour description of every pressing, all 40 million rows, in the list the AI sorted once at build time. That takes about a tenth of a second too.
  • Finding the people on my shelf means going through 256 million credits, which takes a third of a second.
  • What to buy next reads 111 million person-to-album edges.
  • And the 40 hours come straight out of 182 million tracks.
04

Run it yourself

You need clickhouse, discogskit, and your own Discogs collection export in the repo root. Then:

./build.sh --dump 20261101   # first time: download and load the dump
./build.sh                   # after that: rebuild the page
./dev/live.sh                # optional: a local server for Run live

With ./dev/live.sh running, press Run live and connect to http://localhost:8123 as web, password vinyl-local.
